# 整节课程模板模块需求与异常流程文档

## 1. 背景与目标

当前课程编辑端已经支持热身模板、正式组模板、冷身模板三类分段模板。整节课程模板模块用于把一节课的完整结构沉淀为可复用模板，减少重复编课成本，并保证同一课程包内的课程结构、屏幕数量、站点信息、Pod 规则和热身/冷身动作可以稳定复用。

模块目标：

- 支持将一节已配置完整的课程保存为“整节课程模板”。
- 支持从整节课程模板创建一门新课程，新课程继承模板结构但生成新的课程 ID 与内部节点 ID。
- 支持编辑已有整节课程模板，更新后不自动影响已经基于该模板创建的课程。
- 支持课程包维度隔离，编课账号只能查看和使用自己授权课程包内的整节课程模板。
- 保证模板中的动作引用、Logo、屏幕数量、站点信息、Pod 规则、正式组占位规则在保存和复用时可校验、可提示、可追踪。

## 2. 核心概念

### 2.1 整节课程模板

整节课程模板是一个可复用的课程脚本快照，覆盖课程元信息、热身、正式训练、冷身、课程计划、Logo 引用、屏幕结构与 Pod 配置。

整节课程模板不是实际课程，不直接参与排课，不直接下发到 TV。只有通过“从模板创建课程”生成课程后，才可进入课程库、排课和 TV 同步链路。

### 2.2 与现有分段模板的区别

- 热身模板：只保存 `warmup` 瀑布流动作列表。
- 冷身模板：只保存 `cooldown` 瀑布流动作列表。
- 正式组模板：只保存一个 `videoGroup`。
- 整节课程模板：保存完整 `CourseScript` 结构，并补充课程包、Logo、站点与模板元信息。

### 2.3 模板快照原则

整节课程模板保存的是当时的课程结构快照。模板后续编辑不会级联修改已创建课程；已创建课程后续编辑也不会反向修改来源模板，除非用户明确执行“覆盖保存为模板”。

## 3. 数据范围

### 3.1 模板基础信息

整节课程模板至少包含：

- 模板 ID：服务端主键，保存后生成。
- 模板唯一业务 ID：按日期时间区分，例如 `full-course-template-20260523-143012`。
- 模板名称：必填，默认可使用课程名加日期时间后缀。
- 模板描述：选填，用于说明适用场景、强度或教练备注。
- 所属课程包 ID：必填，用于权限和数据隔离。
- 来源课程 ID：选填，记录该模板最初从哪门课程保存而来。
- 创建人、更新人、创建时间、更新时间。
- 模板状态：建议支持 `draft`、`active`、`archived`，第一期可只使用 `active`。

### 3.2 课程名与 Logo

模板保存课程名和 Logo 引用，但从模板创建课程时应允许用户改写课程名。

- `courseName`：模板中的默认课程名。创建课程时作为初始值，不要求与模板名称一致。
- `logoMedia`：保存 Logo 媒体资源引用，不复制二进制文件。
- Logo 缺失或资源失效时，模板仍可打开，但创建课程前需要提示“Logo 资源不可用，可重新上传或继续无 Logo 创建”。
- 如果课程包对品牌 Logo 有固定要求，创建课程时以当前课程包策略优先，模板 Logo 作为默认值。

### 3.3 屏幕数量

整节课程模板必须保存正式训练中每个视频组的屏幕数量：

- `screenCount = 1`：单屏瀑布模式，不需要站点输入。
- `screenCount = 3`：三屏站点模式，每个屏幕包含独立动作列表和站点标签。

模板中可以包含多个视频组，每个视频组独立记录 `screenCount`。Pod 绑定视频组时，Pod 的屏幕配置数量必须与视频组屏幕数量一致。

### 3.4 站点信息

三屏站点模式需要保存：

- 屏幕序号：`screenIndex`，仅允许 `1`、`2`、`3`。
- 屏幕标签：例如 `屏幕 1`、`屏幕 2`、`屏幕 3`。
- 动作卡片上的站点编号：例如 `1`、`2`、`3` 或业务允许的站点编码。
- 每屏动作卡片顺序。

站点信息规则：

- 三屏模式下，同一屏幕内的站点编号不能为空。
- 三屏模式下，同一屏幕内站点编号不能重复。
- 单屏模式下不保存站点编号，或保存为空字符串。
- 从模板创建课程时，如果目标课程包或场馆屏幕能力不足以支持三屏，应阻止创建或要求用户切换到支持的课程包。

### 3.5 热身与冷身数量和动作

热身和冷身使用瀑布流结构：

- 每个动作包含动作 ID、动作名、持续秒数。
- 热身动作数量：至少 1 个。
- 冷身动作数量：允许为 0，即冷身可选。
- 每个动作时长必须大于 0 秒。
- 动作 ID 必须能在当前账号可见的动作库中找到。

保存模板时应保留动作顺序。若动作后续被删除或账号无权访问，模板仍可展示动作名快照，但创建课程时需要提示用户修复动作引用。

### 3.6 正式组占位与规则

正式训练包含视频组和 Pod：

- 视频组保存屏幕数量、屏幕列表、动作卡片和站点信息。
- Pod 保存名称、绑定视频组 ID、站点流转方式、结束方式、各屏规则。
- Pod 屏幕规则保存循环次数、换站休息秒数、组配置列表。
- 组配置保存 work 秒数和 rest 秒数。

正式组占位规则：

- 模板至少需要 1 个视频组。
- 模板至少需要 1 个 Pod。
- 每个视频组的每个屏幕至少需要 1 个动作卡片。
- 每个动作卡片必须选择动作；如果允许占位保存，则占位模板只能保存为 `draft`，不能用于创建课程。
- Pod 必须绑定有效视频组。
- Pod 屏幕数量必须与绑定视频组一致。
- 单屏视频组的 Pod 规则按单屏瀑布模式处理。
- 三屏视频组的 Pod 规则按三屏站点模式处理。

### 3.7 Pod 规则

Pod 规则包含：

- `stationFlow = NORMAL`：正常站点流转。
- `stationFlow = SWITCH`：换站流转，仅允许绑定三屏视频组。
- `ending = HYDRATE`：Pod 结束后进入补水。
- `ending = MOVE_ZONE`：Pod 结束后提示更换区域。
- `ending = FINISH`：课程结束。

Pod 校验规则：

- 最后一个 Pod 必须是 `FINISH`。
- 非最后一个 Pod 不能是 `FINISH`。
- 如果任意 Pod 结束方式为 `HYDRATE` 或 `MOVE_ZONE`，课程默认补水/换区时长必须大于 0。
- 同一个 Pod 内各屏总时长必须一致。
- `SWITCH` 模式下必须绑定三屏视频组。
- `SWITCH` 模式下，每个屏幕动作数量必须为偶数。
- 每个屏幕循环次数必须大于 0。
- 每个 work 秒数必须大于 0。
- 每个 rest 秒数不能小于 0。
- 换站休息秒数不能小于 0。

## 4. 权限与课程包边界

### 4.1 超级管理员

超级管理员可以：

- 查看所有课程包下的整节课程模板。
- 在任意课程包内创建、编辑、归档、删除模板。
- 将模板复制到其他课程包。
- 从任意模板创建课程，并选择目标课程包。

### 4.2 编课账号

编课账号可以：

- 只查看被授权课程包内的整节课程模板。
- 只使用被授权课程包内的模板创建课程。
- 只把自己可编辑的课程保存为模板。
- 不允许把模板保存到未授权课程包。

### 4.3 课程包边界

- 整节课程模板必须绑定一个课程包。
- 从模板创建课程时，默认创建到模板所属课程包。
- 如果允许跨课程包创建，必须校验当前账号同时具备来源课程包读取权限和目标课程包写入权限。
- 模板中的动作引用必须在目标课程包可用范围内。若目标课程包无法访问部分动作，应阻止创建并列出缺失动作。
- 模板不直接参与排课；排课仍只能选择当前课程包内的实际课程。

## 5. 唯一 ID 与日期时间规则

整节课程模板需要有服务端主键和业务唯一 ID 两套标识。

- 服务端主键：数据库自增 ID 或 UUID，用于接口寻址。
- 业务唯一 ID：用于脚本内追踪和复制来源，格式建议为 `full-course-template-YYYYMMDD-HHmmss`。
- 从模板创建课程时，课程脚本内的 `metadata.id` 必须重新生成，建议格式为 `course-YYYYMMDD-HHmmss`。
- 模板内部所有可编辑节点 ID 需要重新生成，避免多个课程共享同一前端节点 ID。
- 日期时间使用服务端时间生成，避免客户端时区和本地时间不一致。
- 同一秒内重复创建时，应追加短随机后缀，例如 `full-course-template-20260523-143012-a8f3`。

## 6. Happy Flow

### 6.1 从课程保存为整节课程模板

1. 用户进入课程编辑页，并选择当前课程包。
2. 用户打开一门已有课程或完成新课程编辑。
3. 用户点击“保存为整节课程模板”。
4. 系统弹出保存弹窗，展示模板名称、所属课程包、描述、是否包含 Logo。
5. 用户确认保存。
6. 系统执行完整课程校验，包括课程名、热身、正式训练、Pod、冷身和动作引用。
7. 校验通过后，系统生成模板业务唯一 ID。
8. 系统保存模板快照。
9. 页面提示“整节课程模板已保存”。
10. 模板出现在当前课程包的整节课程模板列表中。

### 6.2 从整节课程模板创建课程

1. 用户进入课程库，确认已选择课程包。
2. 用户点击“从整节课程模板创建课程”。
3. 系统展示当前课程包内可用模板列表。
4. 用户选择模板。
5. 系统展示创建确认页，允许修改课程名、课程版本、课程设计者、课程类型和 Logo。
6. 用户确认创建。
7. 系统校验模板动作、Logo、课程包权限和屏幕能力。
8. 系统克隆模板脚本，重新生成课程 ID、内部节点 ID、视频组 ID、Pod ID、卡片 ID。
9. 系统创建新课程，并绑定当前课程包。
10. 页面打开新课程编辑页，提示“已从模板创建课程”。

### 6.3 编辑已有整节课程模板

1. 用户进入整节课程模板列表。
2. 用户选择一个有权限编辑的模板。
3. 系统打开模板编辑页，结构与课程编辑页一致，但不参与排课。
4. 用户修改课程名、Logo、热身、正式训练、冷身、Pod 规则等内容。
5. 用户点击“保存模板”。
6. 系统执行完整校验。
7. 校验通过后，更新模板快照和更新时间。
8. 页面提示“整节课程模板已更新”。
9. 已经由该模板创建的课程不受影响。

### 6.4 复制整节课程模板

1. 用户在模板列表选择“复制模板”。
2. 系统生成新模板名称，默认追加日期时间后缀。
3. 系统重新生成模板业务唯一 ID 和内部节点 ID。
4. 用户确认所属课程包。
5. 系统保存为独立模板。

## 7. Bad Flow / 异常 Case

### 7.1 未选择课程包

触发场景：

- 用户尝试创建课程、保存模板或从模板创建课程，但当前没有选中课程包。

系统行为：

- 阻止操作。
- 提示“请先选择课程包”。
- 不发起保存请求。

### 7.2 无课程包权限

触发场景：

- 编课账号访问未授权课程包的模板。
- 编课账号尝试把模板保存到未授权课程包。
- 编课账号使用其他课程包模板创建课程。

系统行为：

- 前端不展示无权模板。
- 服务端二次校验权限。
- 返回权限错误时提示“无权访问该课程包模板”。

### 7.3 模板名称为空或重复

触发场景：

- 保存模板时模板名称为空。
- 同一课程包内存在同名模板。

系统行为：

- 名称为空：阻止保存，提示“模板名称不能为空”。
- 名称重复：建议允许保存但提示用户确认，或阻止并提示“当前课程包已存在同名模板”。第一期建议阻止重复，避免运营误用。

### 7.4 课程基础信息不完整

触发场景：

- 课程名为空。
- 课程设计者为空。
- 课程版本为空。

系统行为：

- 保存为 active 模板或创建课程时阻止。
- 若支持 draft 模板，可保存草稿但不可用于创建课程。

### 7.5 热身为空

触发场景：

- 热身没有动作。

系统行为：

- 阻止保存为 active 模板。
- 提示“热身至少需要一个动作”。

### 7.6 冷身为空

触发场景：

- 冷身没有动作。

系统行为：

- 允许保存和创建课程。
- 摘要中展示“无冷身”。

### 7.7 动作缺失或无权限

触发场景：

- 模板引用的动作已删除。
- 当前账号无权访问模板中的动作。
- 跨课程包创建时目标课程包不包含相关动作。

系统行为：

- 模板详情可打开，并展示动作名快照。
- 创建课程或保存 active 模板时阻止。
- 弹窗列出缺失动作名称和所在位置，例如“热身第 2 个动作”“视频组 A / 屏幕 1 / 第 3 个卡片”。

### 7.8 Logo 资源不可用

触发场景：

- Logo 媒体记录不存在。
- Logo URL 失效。
- 当前账号无权访问 Logo。

系统行为：

- 不阻止打开模板。
- 创建课程时提示“Logo 资源不可用，可移除 Logo 后继续”。
- 用户选择继续时，新课程 Logo 置空。

### 7.9 正式训练为空

触发场景：

- 没有视频组。
- 没有 Pod。

系统行为：

- 阻止保存 active 模板和从模板创建课程。
- 提示“正式训练至少需要一个视频组和一个 Pod”。

### 7.10 视频组屏幕数量异常

触发场景：

- `screenCount` 不是 1 或 3。
- 视频组声明三屏，但实际屏幕数量不足 3。
- 视频组声明单屏，但实际有多个屏幕。

系统行为：

- 阻止保存和创建。
- 提示“视频组只允许单屏或三屏，且屏幕数量必须一致”。

### 7.11 站点编号为空或重复

触发场景：

- 三屏视频组中任一屏幕的动作卡片站点编号为空。
- 同一屏幕内站点编号重复。

系统行为：

- 阻止保存 active 模板和创建课程。
- 提示具体视频组、屏幕和重复站点编号。

### 7.12 Pod 绑定失效

触发场景：

- Pod 的 `videoGroupId` 找不到对应视频组。
- 编辑模板删除视频组后，Pod 未重新绑定。

系统行为：

- 阻止保存和创建。
- 提示“Pod 未关联到有效的视频组”。

### 7.13 Pod 各屏总时长不一致

触发场景：

- 同一 Pod 内不同屏幕由于动作数、循环次数、work/rest、换站休息不同导致总时长不一致。

系统行为：

- 阻止保存和创建。
- 提示“Pod 的各屏总时长必须一致”。
- 建议在 UI 中提供“复制规则到其他屏幕”入口。

### 7.14 SWITCH 规则不满足

触发场景：

- `SWITCH` Pod 绑定了单屏视频组。
- `SWITCH` Pod 绑定的三屏视频组中某屏动作数量为奇数。

系统行为：

- 阻止保存和创建。
- 提示“SWITCH 必须绑定三屏视频组，且每屏动作数量必须为偶数”。

### 7.15 Pod 结束方式异常

触发场景：

- 最后一个 Pod 不是 `FINISH`。
- 非最后一个 Pod 使用 `FINISH`。

系统行为：

- 阻止保存和创建。
- 可提供“一键修正 Pod 结束方式”，自动将最后一个 Pod 设为 `FINISH`，非最后 Pod 的 `FINISH` 改为 `HYDRATE`。

### 7.16 补水/换区时长缺失

触发场景：

- 存在 `HYDRATE` 或 `MOVE_ZONE` Pod，但默认补水/换区时长小于等于 0。

系统行为：

- 阻止保存和创建。
- 提示“当前课程包含补水或换区 Pod，请填写补水 / 换区时长”。

### 7.17 并发编辑冲突

触发场景：

- 用户 A 和用户 B 同时编辑同一个模板。
- 用户 B 先保存，用户 A 再保存旧版本。

系统行为：

- 保存请求携带 `updatedAt` 或版本号。
- 服务端发现版本不一致时返回冲突。
- 前端提示“模板已被其他人更新，请刷新后再编辑”。
- 不自动覆盖远端内容。

### 7.18 网络或服务端保存失败

触发场景：

- 网络断开。
- 上传 Logo 失败。
- 服务端返回 5xx 或数据库错误。

系统行为：

- 保留当前编辑内容。
- 展示错误信息。
- 用户可重试保存。
- 不应生成半成品 active 模板；若服务端已创建但后续步骤失败，应回滚或标记为 draft。

### 7.19 从模板创建课程时课程名冲突

触发场景：

- 当前课程包内已存在同名课程。

系统行为：

- 默认在课程名后追加日期时间后缀，例如 `基础燃脂 20260523 143012`。
- 用户也可以手动改名。
- 不建议静默覆盖已有课程。

### 7.20 删除或归档模板

触发场景：

- 用户删除或归档模板。

系统行为：

- 删除前二次确认。
- 已由该模板创建的课程不受影响。
- 如果需要保留审计，建议第一期使用归档，不做物理删除。

## 8. 保存逻辑

### 8.1 新建模板保存

保存入口：

- 课程编辑页：“保存为整节课程模板”。
- 整节课程模板页：“新建模板”。

保存步骤：

1. 收集当前课程脚本、Logo、课程类型、课程包 ID。
2. 生成或填写模板名称。
3. 执行完整校验。
4. 规范化脚本结构，补齐必要默认值。
5. 生成模板业务唯一 ID。
6. 保存模板快照。
7. 刷新模板列表。

### 8.2 覆盖保存

覆盖保存仅在用户明确选择“覆盖已有模板”时发生。

规则：

- 必须确认目标模板 ID。
- 必须校验用户对目标模板所属课程包有写权限。
- 覆盖后更新模板快照和更新时间。
- 不影响已创建课程。
- 不改变已创建课程的来源记录。

### 8.3 草稿保存

如果支持草稿：

- 草稿允许动作未选择、正式组占位未填完。
- 草稿不可用于创建课程。
- 草稿列表需要明显标识。
- 用户点击“启用模板”时必须通过完整校验。

第一期若不做草稿，所有保存都按 active 模板校验。

## 9. 从模板创建课程逻辑

从模板创建课程必须是深拷贝，不允许复用模板内部节点 ID。

创建规则：

- 新课程 `id` 由服务端生成。
- 新课程 `script.metadata.id` 重新生成。
- 新课程名称默认来自模板课程名，并追加日期时间后缀以避免重名。
- 新课程课程包 ID 默认使用当前选中的课程包。
- 新课程 Logo 默认使用模板 Logo 引用，若资源不可用则置空或要求重新选择。
- 新课程的热身、冷身、视频组、屏幕、动作卡片、Pod、Pod 屏幕、Pod 组配置全部重新生成内部 ID。
- 动作 ID 保持引用同一动作库资源。
- 课程类型默认复制模板中的类型，若目标课程包不支持某些类型，应提示用户重新选择。
- 创建成功后打开课程编辑页，用户可继续修改并保存。

来源追踪建议：

- 新课程记录 `sourceTemplateId`。
- 新课程记录 `sourceTemplateUniqueId`。
- 新课程记录 `createdFromTemplateAt`。

## 10. 编辑已有模板逻辑

模板编辑页应复用课程编辑体验，但需要区分以下行为：

- 保存按钮文案为“保存模板”，不是“保存课程”。
- 不展示排课相关入口。
- 不允许直接发布到 TV。
- 可以编辑课程名、Logo、热身、正式训练、冷身、课程计划和 Pod 规则。
- 可以从现有热身/冷身/正式组模板套用到整节课程模板中。
- 保存模板时只更新模板，不更新任何课程。
- 编辑过程中若切换课程包，需要提示会影响模板归属和可见范围。

建议增加模板变更提示：

- 如果模板已被用于创建课程，编辑保存前提示“修改模板不会影响已创建课程”。
- 如果用户想同步到某门课程，需要另走“从模板重新套用到课程”的显式流程，第一期可不支持。

## 11. 接口建议

整节课程模板建议与现有 `/api/templates` 分离，避免和分段模板混淆。

建议接口：

- `GET /api/full-course-templates?coursePackageId=<id>`：获取当前课程包模板列表。
- `POST /api/full-course-templates`：创建整节课程模板。
- `GET /api/full-course-templates/:id`：获取模板详情。
- `PUT /api/full-course-templates/:id`：更新模板。
- `POST /api/full-course-templates/:id/create-course`：从模板创建课程。
- `POST /api/full-course-templates/:id/duplicate`：复制模板。
- `POST /api/full-course-templates/:id/archive`：归档模板。
- `DELETE /api/full-course-templates/:id`：删除模板，若采用归档策略则可不开放。

创建模板请求核心字段：

```json
{
  "uniqueId": "full-course-template-20260523-143012",
  "name": "基础燃脂整节模板",
  "description": "三屏站点，适合新手燃脂课",
  "coursePackageId": 1,
  "sourceCourseId": 12,
  "courseName": "基础燃脂",
  "logoMedia": null,
  "typeIds": [1, 2],
  "script": {}
}
```

从模板创建课程请求核心字段：

```json
{
  "coursePackageId": 1,
  "name": "基础燃脂 20260523 143012",
  "creator": "Coach A",
  "version": "v1",
  "typeIds": [1],
  "logoMedia": null
}
```

## 12. UI 入口建议

课程库：

- 新增“整节课程模板”入口或 tab。
- 新增“从模板创建课程”按钮。
- 课程编辑页新增“保存为整节课程模板”按钮。

整节课程模板列表：

- 展示模板名称、所属课程包、课程名、屏幕模式、Pod 数、热身动作数、冷身动作数、更新时间、创建人。
- 支持搜索、课程包筛选、状态筛选。
- 支持编辑、复制、归档、删除、创建课程。

从模板创建课程弹窗：

- 展示模板摘要。
- 允许改课程名、版本、设计者、课程类型和 Logo。
- 展示异常校验结果。
- 校验通过后才能确认创建。

## 13. 验收标准

- 可以从一门完整课程保存为整节课程模板。
- 可以在当前课程包模板列表中看到该模板。
- 可以从该模板创建新课程，新课程拥有新的课程 ID 和内部节点 ID。
- 新课程保留模板中的课程名默认值、Logo 引用、热身动作、冷身动作、视频组、站点信息和 Pod 规则。
- 编辑模板不会影响已创建课程。
- 编辑已创建课程不会影响来源模板。
- 未授权课程包的模板不可见、不可用、不可保存。
- 动作缺失、Pod 规则错误、站点重复、屏幕数量异常等 bad flow 均有明确错误提示。
- 同名课程创建时不会覆盖已有课程，默认追加日期时间区分。
- 所有唯一业务 ID 使用日期时间生成，并能处理同秒重复创建。

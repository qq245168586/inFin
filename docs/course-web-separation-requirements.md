# Course Web 独立拆分需求文档

## 1. 背景

当前系统里“课程编辑端”和“场馆管理端”仍然存在功能边界混在一起的问题。后续需要把课程制作、动作录入、模板管理、排课等内容生产能力独立出去，单独作为课程端使用；Admin 只负责平台级管理、场馆、账号、设备和版本，不再承担具体编课工作。

新增子域名：

- `course.infintraining.work`：课程端，负责编课、动作库、模板、课程包和排课。
- `admin.infintraining.work`：管理端，只负责场馆、账号、设备、版本和课程包绑定。
- `coach.infintraining.work`：教练端，负责现场查看课表、预览课程、控制 TV。

`course.infintraining.work` 当前已新增 DNS，但还需要配置 HTTPS 证书与 Nginx 站点。

## 2. 总体目标

- 课程端从 Admin 中完全剥离，独立域名、独立前端入口、独立权限。
- 课程、动作、模板、课程包、排课全部归属课程端。
- Admin 不再编辑课程内容，只管理“哪个场馆使用哪个课程包”。
- 课程本身不绑定场馆，课程可以被多个课程包复用。
- 场馆可以绑定多个课程包，并通过当前选中的课程包获得对应课表。
- Coach 端需要能切换当前控制/展示的课程包，例如拳击馆显示拳击课程包，综合训练馆显示混合训练课程包。
- 账号需要分权：
  - 平台管理员可以管理场馆、账号、设备、版本、课程包绑定。
  - 编课账号只能进入课程端，不能进入 Admin。
  - 编课账号需要限制可编辑和可排课的课程包范围。
  - 场馆/教练账号只能进入 Coach，用于现场操作。

## 3. 系统边界

### 3.1 Course Web：课程端

域名：`https://course.infintraining.work`

面向对象：

- 课程运营人员
- 编课老师
- 内容制作人员

功能范围：

- 动作库
- 动作分类
- 视频上传与批量上传
- 课程编辑
- 热身 / 正式训练 / 冷身模板
- 课程模板
- 课程计划文字内容
- 查看和操作被授权课程包
- 排课日历

不包含：

- 场馆管理
- 课程包创建 / 删除
- 设备绑定
- TV 版本更新
- 场馆账号管理
- MQTT 调试

### 3.2 Admin Web：管理端

域名：`https://admin.infintraining.work`

面向对象：

- 平台管理员
- 运营管理员

功能范围：

- 场馆管理
- 场馆账号管理
- 编课账号管理
- 场馆与课程包绑定
- 场馆设备查看
- TV 设备解绑
- TV App 版本查看与更新指令下发
- 应用版本管理

不包含：

- 动作库录入
- 课程脚本编辑
- 模板编辑
- 课程排课内容编辑

### 3.3 Coach Web：教练端

域名：`https://coach.infintraining.work`

面向对象：

- 场馆教练
- 现场运营人员

功能范围：

- 查看当前场馆今日课表
- 查看课程动作视频
- 预览课程
- 开始 / 暂停 / 继续 / 终止课程
- 展示课程计划到 TV
- 切换当前场馆要显示和控制的课程包
- 查看绑定屏幕在线状态
- 现场扫码绑定 TV

课表来源：

- 当前登录账号绑定的场馆
- 场馆绑定的多个课程包
- Coach 当前选中的课程包
- 当前课程包内的排课数据

## 4. 核心业务模型

### 4.1 课程 Course

课程是可复用的内容资产，不直接绑定场馆。

课程包含：

- 基础信息：名称、设计者、版本、标签
- 热身模块
- 正式训练模块
- 冷身模块
- 课程计划内容
- 视频资源引用
- 脚本校验信息

### 4.2 动作 Action

动作是课程编辑的基础资源。

动作包含：

- 动作名称
- 动作类型 / 分类
- 视频资源
- 视频封面
- 版本信息
- 上传时间

### 4.3 模板 Template

模板用于提升编课效率。

模板类型：

- 热身模板
- 冷身模板
- 正式训练视频组模板
- 课程模板

模板可以在课程编辑时套用。套用模板时如果当前模块已有内容，需要弹窗确认覆盖。

### 4.4 课程包 Course Package

课程包是给场馆使用的一组课程与排课计划。

例子：

- 拳击课程包
- 混合训练课程包
- HYROX 基础课程包
- 私教团课课程包

课程包包含：

- 课程包名称
- 课程包说明
- 包内可用课程列表
- 周排课 / 日历排课
- 更新时间

说明：

- 同一门课程可以被多个课程包复用。
- 同一个课程包可以绑定给多个场馆。
- 同一个场馆可以绑定多个课程包。
- 场馆实际课表来自场馆当前选中的课程包。
- 当前课程包是场馆级状态，不是某个 Coach 浏览器的临时状态。
- 课程包不需要额外发布按钮，完成排课即视为可发布/可使用。

### 4.5 场馆 Venue

场馆只在 Admin 中管理。

场馆包含：

- 场馆名称
- 场馆 ID / namespace
- 绑定账号
- 绑定设备
- 绑定课程包
- 当前课程包
- 当前启用状态
- 当前上课状态

场馆不直接编辑课程，只选择使用哪个课程包。

默认规则：

- 系统需要有一个默认课程包。
- 新建场馆时自动绑定默认课程包，并把默认课程包设为当前课程包。
- 如果场馆需要换课程包，由超级管理员/Admin 在 Admin 端手动绑定或解绑课程包。
- 超级管理员/Admin 可以解绑场馆课程包、绑定新的课程包、设置当前课程包。
- Coach 只能查看当前场馆已绑定的课程包，并在这些课程包之间切换当前课程包，不能绑定或解绑课程包。

### 4.6 账号 Account

账号不限制形式，可以是手机号、文本账号或其它唯一字符串。

账号字段：

- account
- password
- role
- venueId
- enabled
- createdAt
- updatedAt

建议角色：

- `super_admin`：平台管理员，可进入 Admin、Course 和 Coach，拥有全部权限。
- `course_editor`：编课账号，只能进入 Course。
- `venue_operator`：场馆/教练账号，只能进入 Coach。

## 5. 权限需求

### 5.1 平台管理员

可访问：

- Admin Web
- Course Web
- Coach Web（如需要调试）

可操作：

- 创建 / 删除 / 编辑场馆
- 创建 / 禁用账号
- 创建编课账号
- 绑定账号到场馆
- 创建 / 编辑 / 删除课程包
- 授权编课账号可管理的课程包
- 绑定课程包到场馆
- 查看和管理 TV 设备
- 下发 TV 更新
- 管理课程端全部内容

### 5.2 编课账号

可访问：

- Course Web

不可访问：

- Admin Web
- Coach Web

可操作：

- 录入动作
- 上传视频
- 编辑课程
- 管理模板
- 在授权范围内排课

权限范围：

- 编课账号必须绑定一个或多个可管理课程包。
- 编课账号只能编辑授权课程包内的课程和模板。
- 编课账号只能给授权课程包排课。
- 例如拳击编课账号只能编辑拳击课程包，不能编辑或排课综合体能课程包。

不可操作：

- 创建场馆
- 管理设备
- 解绑 TV
- 下发 TV 更新
- 创建场馆账号

### 5.3 场馆/教练账号

可访问：

- Coach Web

不可访问：

- Admin Web
- Course Web

可操作：

- 查看所属场馆课表
- 预览课程
- 控制 TV 播放
- 查看屏幕在线状态
- 扫码绑定本场馆 TV

## 6. Course Web 功能需求

### 6.1 登录

- 使用独立入口 `course.infintraining.work`。
- 登录后根据账号角色判断是否允许进入课程端。
- 非 `super_admin` / `course_editor` 账号不能进入。
- 超级管理员保留课程端入口，并拥有课程端全部能力，不受课程包授权范围限制。
- 登录页不再出现“测试环境 / 正式环境”概念，只是选择或输入账号。

### 6.2 动作库

- 支持动作列表、搜索、分类筛选。
- 支持单个上传动作视频。
- 支持批量上传动作视频。
- 批量上传前弹窗提示命名规则。
- 视频命名规则示例：`动作名-类型.mp4`。
- 支持视频封面预览。
- 支持动作类型管理。

### 6.3 课程库

- 新建课程。
- 编辑课程。
- 删除课程。
- 复制课程。
- 课程结构保留：
  - 热身
  - 正式训练
  - 冷身，可选
- 支持课程计划内容编辑。
- 支持保存草稿。
- 支持发布版本。

### 6.4 模板库

- 热身模板。
- 冷身模板。
- 正式训练视频组模板。
- 课程模板。
- 模板可命名、编辑、删除、套用。

### 6.5 课程包管理

- 课程包由 Admin 创建、编辑和删除。
- Course Web 只展示当前登录账号被授权的课程包。
- 超级管理员在 Course Web 可查看和操作全部课程包。
- 编课账号只能进入授权课程包进行内容维护和排课。
- 将课程加入授权课程包。
- 从授权课程包移除课程。
- 管理授权课程包排课。
- 不设置额外“发布课程包”按钮，课程包排好课后即视为可被场馆使用。
- 编课账号不能创建、删除或授权课程包。

### 6.6 排课

- 排课属于课程包，不属于单个场馆。
- 课程包内可以配置周一到周日的课程安排。
- 支持按日期时间排课。
- 支持复制上周 / 复制某天排课。
- 支持日历视图，课程卡片根据时间定位。
- 课程包排课完成后即可被 Admin 绑定到场馆。
- 排课动作本身就是课程包的发布机制，不再额外设计发布流程。

## 7. Admin Web 功能需求

### 7.1 场馆管理

- 新建场馆。
- 编辑场馆。
- 删除场馆。
- 查看场馆绑定账号。
- 查看场馆绑定课程包。
- 查看场馆绑定设备。

### 7.2 账号管理

需要独立账号管理模块，而不是只在场馆详情里临时创建。

功能：

- 创建账号。
- 设置密码。
- 设置角色。
- 禁用 / 启用账号。
- 查看账号当前绑定的场馆。
- 查看账号是否未绑定场馆。

约束：

- 一个场馆可以绑定多个场馆/教练账号。
- 一个场馆可以绑定多个编课账号不是必须项，编课账号默认不绑定场馆。
- 一个场馆/教练账号暂时只能绑定一个场馆。

### 7.3 绑定账号到场馆

交互：

- 在场馆详情中点击“绑定账号”。
- 弹出账号搜索框。
- 输入账号关键字后，像联系人筛选一样过滤已创建账号。
- 只能选择未绑定场馆或允许转移的账号。
- 绑定后账号获得该场馆的 Coach 权限。

### 7.4 编课账号管理

Admin 中新增“编课者”模块。

功能：

- 创建编课账号。
- 设置账号密码。
- 启用 / 禁用编课账号。
- 授权该账号可编辑的课程包。
- 取消该账号对某个课程包的编辑权限。
- 查看最近登录时间。
- 查看该账号创建或编辑过的课程/课程包。

编课账号创建后，管理员把账号密码发给对方，对方登录 `course.infintraining.work` 使用。

### 7.5 课程包管理

Admin 中新增“课程包管理”模块。

功能：

- 创建课程包。
- 编辑课程包基础信息。
- 删除课程包。
- 查看课程包绑定了哪些场馆。
- 查看课程包授权给了哪些编课账号。
- 授权 / 取消授权编课账号。

说明：

- 课程包是权限和排课的边界。
- 课程包创建由 Admin 完成。
- 课程包内具体课程内容和排课由 Course Web 完成。
- 超级管理员可以在 Course Web 操作所有课程包。

### 7.6 课程包绑定

场馆详情中新增“课程包绑定”区域。

功能：

- 查看当前绑定课程包。
- 搜索课程包。
- 绑定课程包。
- 解绑课程包。
- 设置默认课程包。
- 查看场馆是否正在上课。

说明：

- 一个场馆可以绑定多个课程包。
- 新建场馆默认绑定系统默认课程包。
- 只有超级管理员/Admin 可以给场馆绑定、解绑课程包。
- Coach 端需要提供课程包切换入口，用于在当前场馆已绑定的课程包中选择当前展示/控制的课程包。
- Coach 不能绑定或解绑课程包。
- 课程包切换状态适用于整个场馆，场馆选择了哪个课程包，Coach 和 TV 就显示哪个课程包的课程。
- TV 获取课表时读取当前场馆当前选中课程包的排课。
- TV 收到课程包切换同步指令后，需要切换到该课程包，并下载/校验该课程包当天课表所需资源。
- 场馆绑定、解绑或切换当前课程包后，需要立即触发课表同步。
- 同步沿用现有控制链路：Coach/Admin 发起 HTTP 请求到服务端或 mqtt-client 服务，再由 mqtt-client 统一发布 MQTT 指令给 TV。
- 如果当前场馆正在上课，Coach 和 Admin 都不能切换、绑定或解绑课程包，必须等待课程结束后再操作。
- 如果场馆没有绑定课程包，Coach 和 TV 显示“当前场馆未配置课程包”。

### 7.7 设备管理

场馆详情继续展示设备状态：

- 屏幕编号
- 设备 ID
- 在线 / 离线
- 当前 App 版本
- 当前状态

操作：

- 解绑设备。
- 下发 TV App 更新。
- 查看设备最近心跳时间。

## 8. Server 需求

### 8.1 域名与前端服务

需要拆分静态站点：

- `course.infintraining.work` -> Course Web 构建产物
- `admin.infintraining.work` -> Admin Web 构建产物
- `coach.infintraining.work` -> Coach Web 构建产物
- `download.infintraining.work` -> APK 下载页
- `git.infintraining.work` -> Git 服务
- `api.infintraining.work` -> API 服务

`course.infintraining.work` 需要配置 HTTPS 证书。

### 8.2 权限接口

登录后服务端需要返回：

- token
- account
- role
- allowedClients
- venueId

客户端根据 `allowedClients` 决定是否允许进入：

- `admin`
- `course`
- `coach`

### 8.3 课程包接口

建议新增：

- `GET /api/course-packages`
- `POST /api/course-packages`
- `GET /api/course-packages/:id`
- `PUT /api/course-packages/:id`
- `DELETE /api/course-packages/:id`
- `POST /api/course-packages/:id/courses`
- `DELETE /api/course-packages/:id/courses/:courseId`
- `GET /api/course-packages/:id/schedules`
- `PUT /api/course-packages/:id/schedules`
- `GET /api/course-packages/:id/editors`
- `POST /api/course-packages/:id/editors`
- `DELETE /api/course-packages/:id/editors/:accountId`

### 8.4 场馆绑定课程包接口

建议新增：

- `GET /api/venues/:venueId/course-packages`
- `POST /api/venues/:venueId/course-packages`
- `DELETE /api/venues/:venueId/course-packages/:packageId`
- `PUT /api/venues/:venueId/default-course-package`
- `POST /api/venues/:venueId/course-packages/sync`

### 8.5 账号管理接口

建议新增：

- `GET /api/accounts`
- `POST /api/accounts`
- `GET /api/accounts/:id`
- `PUT /api/accounts/:id`
- `DELETE /api/accounts/:id`
- `POST /api/venues/:venueId/accounts`
- `DELETE /api/venues/:venueId/accounts/:accountId`
- `GET /api/accounts/:id/course-packages`
- `POST /api/accounts/:id/course-packages`
- `DELETE /api/accounts/:id/course-packages/:packageId`

### 8.6 Coach / TV 课表接口调整

现有课表接口需要按以下链路取课：

1. 根据登录账号找到 `venueId`。
2. 根据 `venueId` 找到该场馆绑定的课程包列表。
3. 读取该场馆当前选中的课程包；如果没有则读取默认课程包。
4. 根据当前课程包排课生成今日课表。
5. TV 和 Coach 都只看到所属场馆当前课程包的排课。

不能直接读取全局排课。

## 9. 数据迁移需求

现有数据需要迁移为：

- 全局课程库。
- 全局动作库。
- 全局模板库。
- 课程包。
- 课程包排课。
- 场馆绑定课程包。
- 账号角色与权限。

迁移原则：

- 不删除现有课程。
- 不删除现有动作视频。
- 不破坏现有 `db.json`。
- 所有迁移脚本必须先备份数据库。
- 迁移后保留回滚备份。

## 10. 部署需求

### 10.1 DNS

需要确保以下解析到服务器：

- `course.infintraining.work`
- `admin.infintraining.work`
- `coach.infintraining.work`
- `api.infintraining.work`

### 10.2 HTTPS

需要为 `course.infintraining.work` 申请并配置 HTTPS 证书。

建议统一证书策略：

- 优先使用通配符证书：`*.infintraining.work`
- 或逐个子域名签发证书

### 10.3 Nginx

需要为 Course Web 单独配置 server block，不能复用 Admin 的入口。

目标：

- `https://course.infintraining.work` 打开课程端。
- `https://admin.infintraining.work` 打开管理端。
- 两个前端构建目录完全分开。

## 11. 验收标准

### 11.1 课程端

- 打开 `course.infintraining.work` 进入课程端登录页。
- 编课账号能登录课程端。
- 编课账号不能登录 Admin。
- 超级管理员能登录课程端并操作全部课程包。
- 可以管理动作库。
- 可以编辑课程。
- 可以管理模板。
- 编课账号只能看到被授权课程包。
- 编课账号只能在被授权课程包内排课。

### 11.2 管理端

- Admin 不再展示课程编辑、动作库、模板、排课入口。
- Admin 可以创建场馆。
- Admin 可以创建账号。
- Admin 可以创建课程包。
- Admin 可以授权编课账号可编辑哪些课程包。
- Admin 可以绑定账号到场馆。
- Admin 可以绑定课程包到场馆。
- Admin 可以解绑场馆课程包。
- Admin 可以看到场馆是否正在上课。
- Admin 绑定或切换场馆课程包后能触发 TV 课表同步。
- 场馆正在上课时，Admin 不能切换、绑定或解绑课程包。
- Admin 可以查看场馆设备状态。
- Admin 可以对单个 TV 设备下发更新。

### 11.3 Coach / TV

- Coach 登录后只看到自己场馆绑定课程包的课表。
- Coach 可以查看当前场馆已绑定课程包，并切换当前课程包。
- Coach 不能绑定或解绑课程包。
- 场馆正在上课时，Coach 不能切换课程包。
- Coach 切换场馆当前课程包后，TV 会同步切换课程包并下载/校验对应课程资源。
- TV 绑定场馆后只同步该场馆当前课程包的课表。
- 未绑定课程包的场馆不显示其它场馆课程。
- 不同场馆之间不能互相看到或控制课程。

## 12. 已确认决策

- 一个场馆允许绑定多个课程包。
- 系统需要一个默认课程包，新建场馆默认绑定并启用默认课程包。
- Coach 端需要支持切换当前课程包。
- Coach 只能切换已绑定课程包，不能绑定或解绑课程包。
- 课程包切换状态按场馆全局保存，Coach 和 TV 都以场馆当前课程包为准。
- TV 收到课程包切换后，需要同步切换并下载/校验该课程包当天课表资源。
- 课程运行中，Coach 和 Admin 都不能切换、绑定或解绑课程包，必须等待课程结束。
- Admin 需要显示每个场馆是否正在上课。
- 课程包不需要额外发布机制，排课完成即视为可发布/可使用。
- 编课账号必须限制可编辑和可排课的课程包范围。
- 课程端保留超级管理员入口，超级管理员拥有全部课程端权限。
- 场馆绑定课程包后需要立即同步课表，MQTT 仍通过 HTTP 调用 mqtt-client 服务统一转发。

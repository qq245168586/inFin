# 04. 复杂度、工作量与交付边界

## 1. 评估前提

本项目有两个同时成立的事实：

1. 如果外包从 0 做出商用品质版本，替代成本不会等同于普通后台系统，因为它涉及多端、多屏、多场馆、多媒体、多实时链路和现场设备。
2. 当前系统是由 1 人在约 4 个月内，借助 AI/vibe coding 高强度开发完成；因此评估现有项目出售或授权时，也不能简单按传统团队重做成本机械套用。

建议专家独立评估以下问题：

- 从 0 重做同等功能的工作量；
- 现有系统完成度和可维护性；
- 代码质量是否支撑第三方接手；
- 现场商用验证程度；
- 买方是否需要源码、IP、复制权、二开权；
- 是否包含交接、部署、培训、维护、新功能；
- 未来是否允许复制到多店、直营店、加盟店或托管店。

本文件不提供具体金额判断，仅提供交付范围边界和复杂度说明。

## 2. 从 0 重做的模块范围

| 模块 | 工作内容 | 复杂度判断 |
| --- | --- | --- |
| 后端基础 | 登录、权限、用户、场馆、课程包、排课、媒体、TV session、OpenAPI | 高 |
| Course 编课端 | 动作库、视频上传、课程脚本、模板、Pod、站点、训练参数、排课 | 很高 |
| Admin 管理端 | 场馆、账号、课程包、TV 设备、版本更新、绑定关系 | 中高 |
| Coach 控课端 | 今日课表、预览、开始、暂停、继续、结束、刷新 TV、绑定屏幕 | 高 |
| Android TV 客户端 | 二维码绑定、多屏播放、视频缓存、MQTT、心跳、APK 更新、断网恢复 | 很高 |
| MQTT 与实时链路 | 控制消息、session 消息、场馆 namespace 隔离、日志排查 | 高 |
| 媒体与缓存 | 上传、缩略图、checksum、daily bundle、HTTP/Nginx 交付、TV 本地缓存 | 高 |
| 运维与部署 | 多域名、Nginx、systemd、APK 下载、日志、线上排查 | 中高 |
| 测试与现场联调 | 多屏同步、弱网、弱硬件、课程时序一致性、真实门店验收 | 很高 |

## 3. AI/vibe coding 的影响

AI 辅助会降低部分编码和脚手架成本，但不会消除以下成本：

- 产品理解；
- 业务建模；
- 课程脚本和 TV 播放时序一致性；
- Android TV 弱硬件调试；
- 现场网络和设备联调；
- 线上 bug 责任；
- 交付文档和长期维护；
- 第三方团队接手成本。

因此，建议专家分别给出：

- 传统团队从 0 重做的工作量判断；
- AI 辅助下从 0 重做的工作量折减判断；
- 现有项目作为半成品/商用原型/可运行系统的资产折扣判断；
- 若交付给第三方团队继续维护，所需补充文档、重构和测试成本。

## 4. 交付模式边界

| 模式 | 包含内容 | 不应默认包含 |
| --- | --- | --- |
| 单店试用授权 | 约定门店使用权、一次部署协助、基础使用说明 | 源码、IP 转让、复制权、二开权、长期维护 |
| 多店授权 | 多个约定门店使用权、部署协助、有限支持 | 完整 IP、任意转售、无限制加盟复制 |
| 源码交付 | 源码、部署说明、一次交接、有限问题答疑 | IP 完整转让、长期维护、大功能开发 |
| 完整 IP 买断 | 源码、IP、部署文档、交接、约定期限内 bug 修复 | 超范围新需求、长期运维、现场长期驻场 |
| 交钥匙交付 | 完整交付、培训、现场联调、一定期限支持 | 新业务模块、持续产品迭代、无限工时支持 |

专家评估商业条款时，建议分别评估这些模式，而不是把所有权利和义务混成一个模糊总包。

## 5. 维护范围边界

维护应从买断/授权中拆出来单独评估。建议至少明确：

- 免费 bug 修复期持续多久；
- 是否包含服务器基础运维；
- 是否包含 TV 设备、MQTT、缓存、播放异常排查；
- 是否包含远程支持；
- 每月包含多少工时；
- 超出工时如何计费；
- 现场支持是否另算差旅和人天；
- 新功能是否应作为独立项目评估；
- 第三方原因造成的问题是否计入维护。

## 6. 新功能边界

以下内容不应默认包含在现有系统买断或基础维护中：

- 会员 CRM；
- 微信小程序；
- 预约签到；
- 支付；
- 营销活动；
- 教练培训管理；
- 运营管理系统；
- 加盟管理；
- 多门店经营看板；
- UI 大改版；
- 数据库重构；
- 硬件采购和现场网络施工。

这些应作为独立需求，由专家单独估算工作量。

## 7. 授权与 IP 边界

如果采用授权模式，建议专家关注：

- IP 和源码是否仍归原开发者；
- 授权门店数量是否明确；
- 是否允许复制到直营、加盟、托管门店；
- 是否允许第三方二次开发；
- 是否允许转售；
- 停止合作后是否继续可用；
- 数据如何迁出；
- 新增门店如何计费；
- 维护责任如何划分。

如果采用买断模式，建议专家关注：

- 源码和 IP 是否完整转让；
- 域名、服务器、数据库、软著、商标是否包含；
- 历史数据和生产环境是否包含；
- 第三方依赖和开源许可证风险；
- 交接文档和培训是否足够；
- 原开发者后续竞业或复用权如何约定；
- 分期付款时源码/IP 交付节点如何绑定。

## 8. 专家应输出的评估结果

建议专家最后给出以下独立判断：

1. 现有项目技术质量评价；
2. 从 0 重做同等功能的工作量评估；
3. 考虑 AI 辅助后的工作量折减评估；
4. 现有系统完成度折扣；
5. 不同交付模式的商业条款建议；
6. 维护服务应如何计价；
7. 新功能单独开发的工作量；
8. 买断或授权时的合同风险；
9. 接手前必须补齐的文档、测试和部署材料。

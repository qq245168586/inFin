# 05. 专家评审清单

可把以下问题直接给专家，让专家逐项判断。

## 1. 技术架构

- 当前多端架构是否合理？
- Server 作为权威状态源、MQTT 作为通知通道的设计是否正确？
- 多场馆 namespace 隔离是否足够？
- Android TV 端是否存在明显架构风险？
- 媒体缓存、checksum、bundle 的设计是否适合健身房现场？
- 目前 JSON/File Store 是否需要在规模化前迁移到数据库？
- Nginx、systemd、部署脚本是否达到商用运维最低要求？

## 2. 代码质量

- 6.5 万行左右代码中，模块边界是否清楚？
- 前端多个 Web 是否复用合理？
- Course 编辑器的状态管理是否可维护？
- TV Android 类拆分是否还能继续扩展？
- 测试覆盖是否足以支撑源码交付、授权或买断？
- 代码是否依赖开发者个人经验过重？
- 是否需要重构后再卖，还是现状可交付？

## 3. 功能完整度

- 现有系统是否已覆盖团课交付的核心闭环？
- 哪些能力属于 MVP，哪些属于商用增强？
- 会员、小程序、培训、运营管理缺口有多大？
- 对外交付时应不应把未来功能排除在合同外？
- 现有文档是否足以让第三方团队接手？

## 4. 复杂度与估价

- 如果从 0 外包重做，专家如何估算各模块工作量？
- 考虑 AI/vibe coding 和 1 人 4 个月开发后，专家如何评估现有系统的资产折扣？
- 完整 IP 买断、源码交付、单店授权、多店授权应如何区分权利和义务？
- 单店试用授权应包含和排除哪些权利？
- 维护费应按月、按工时还是按事件计费？
- 按店授权、分成或长期服务模式应如何设计？

## 5. 商业与法律

- IP、源码、部署权、复制权、二开权是否需要拆开定价？
- 如果买断，付款节点如何和源码/IP交付绑定？
- 如果授权，如何限制复制到其他门店或加盟店？
- 维护和新功能边界如何写进合同？
- 是否需要保留软著、商标、域名、服务器资产？
- 是否需要律师出具 IP 转让/授权协议？

## 6. 建议专家输出的结论

请专家最后给出：

1. 技术质量评价：可交付 / 需重构 / 不建议买断；
2. 重做工作量与成本估算；
3. 买断模式下的交付范围与风险；
4. 授权/分成模式下的权利边界；
5. 维护服务的计量方式和责任边界；
6. 交付风险清单；
7. 合同必须保护的条款。

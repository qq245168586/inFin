# 05. 权属与风险核查清单

## 1. 申请人选择

请先确认著作权人填谁：

- 你个人；
- 已成立公司；
- 未来拟成立公司；
- 你和公司/合伙人共同著作权；
- 你先申请，再授权或转让给公司。

如果目前公司尚未成立，通常更稳妥的路径是：

1. 先由实际开发者个人申请；
2. 后续如需进入公司，再签署软件著作权转让、许可或作价出资协议；
3. 办理著作权转让合同登记或权属变更（如需要）。

## 2. 独立开发确认

逐项确认：

- 核心代码是否由你独立完成；
- 开发是否发生在前雇主工作时间或使用前雇主设备/资源；
- 是否有任何外包人员提交过代码；
- 是否有朋友、教练、运营人员参与具体代码实现；
- 是否已有合同约定代码归某公司或某客户；
- 是否存在口头承诺转让源码或 IP。

## 3. 合作开发风险

如果合伙人只提供业务需求、课程内容、门店场景、测试反馈，一般不当然等于软件共同作者。但如果其参与了代码编写、架构设计、核心算法或可表达的软件设计文档，需要单独评估是否构成合作开发贡献。

建议签署：

- 软件独立开发及权属确认书；
- 业务素材/课程内容授权书；
- 系统试用授权协议；
- 源码/IP 不转让确认条款；
- 后续转让或买断的付款节点条款。

## 4. 开源组件风险

项目使用 React、Vite、NestJS、MQTT、AndroidX、OkHttp、Paho、ZXing 等开源组件。申请软著通常登记的是自研代码表达，不是开源组件本身。提交源代码鉴别材料时：

- 尽量选择自研业务代码；
- 避免提交 `node_modules`、Gradle 缓存、第三方库源码；
- 保留开源组件清单；
- 后续商业转让时检查许可证义务。

## 5. 敏感信息排查

源代码交存前必须排查：

- 服务器 IP、密码、token；
- 数据库真实数据；
- 微信/短信/支付密钥；
- MQTT 用户名密码；
- 第三方 API key；
- 客户真实手机号、姓名、会员信息；
- 其他公司版权声明。

如有敏感信息，应先替换为占位配置或选择其他文件。
